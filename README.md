# 统一角色控制台 · v0.15.1

提供统一角色、本人私聊补充、工作区绑定和覆盖检查，并向已适配插件同步名字与称呼。工具默认接入 DSH 和插件提供的全部可用能力，无需在控制台逐项勾选。控制台本身不改第三方插件代码。名称同步只更新名称字段；私信入口另外通过明确的连接按钮配置。

已适配 DSH 0.2.2-rc.1 提示词组装接口：组装载荷没有工具列表时不再报 `filter` 错误，同时兼容旧接口。

## 小肥鱼桌宠（macOS）

1. 重新加载插件或重启 DeepSeek Harness，打开 **设置 → 大肥鱼工作区 → 桌宠**，直接点 **「打开桌宠」**，无需绑定或先打开任何会话。小肥鱼只显示在独立的透明置顶窗口里，聊天输入框上方不再放角色面板。
2. 在这页调整 **桌宠大小、朗读、待机场景、场景表情和自动轮换时间**。大小为 **20%～100%**，松开滑杆后生效。右键小肥鱼或点 **「大小/动作」** 也可以操作；缩小后移入人物，点 **「⋯」** 打开控制栏。大小和保存后的轮换时间跨启动保留。
3. 勾选 **「启动 DSH 时自动打开桌宠」** 会记住选择，并在当前没有桌宠时立即打开。以后启动 DSH 就会打开全局桌宠，无需进入聊天。手动收回后，本次运行不会自行弹出；取消勾选后改为手动打开。
4. 拖动角色或顶部手柄移动窗口。点 **「对话」** 输入文字并发送，消息发送到最近在 DSH 打开的聊天，对话框会显示去向，切换聊天会保留草稿和桌宠设置。没有可用聊天时仍可播放动作和表情；发送前打开任意会话即可。切换其他应用、最小化 DSH 或关闭设置页时，桌宠继续运行。
5. 在工作区设置或桌宠里点 **「开启朗读」** 听新回答，点「停止播报」打断声音；自动切换聊天去向时保留朗读开关。字幕保留完整回复，语音跳过中英文圆括号中的文字和 emoji。重新打开时不会补读历史回复。
6. 在桌宠对话栏点 **「录音」**，说完点「停止」。最长录制 30 秒，使用 DSH 本地中文 SenseVoice 转写；核对草稿后再发送。首次录音需允许 macOS 访问麦克风。也可以继续用 DSH 原有输入框里的麦克风。
7. 每次只打开一只桌宠。桌宠全局汇总所有正在运行的任务和工具，不再提供会话绑定下拉框。不同会话的轮次和工具分别记录；后台任务的回复不会混入当前聊天或被补读。点 **「显示桌宠」** 找回已有窗口。点桌宠右上角 **×** 或设置中的 **「收回桌宠」** 关闭窗口，之后可从设置重新打开。完全退出 DSH 会同时关闭桌宠。
8. 把小肥鱼拖到当前显示器可用区域的右边缘，松手即可进入 **「右侧探头」**。她只露出半张脸和扶边的小手，窗口随缩放占 24～64 点宽。新回复到来时仍保持收起。点头像对话，再点「对话」收起，右键可以打开设置。沿边上下拖能换位置，向左拖出超过 24 点再松手可恢复普通桌宠。重新打开会记住贴边位置。

随插件提供 Apple Silicon 与 Intel 两种架构的窗口程序，源文件和本机构建脚本位于 `lib/avatar/desktop/`。桌宠复用同一套 Live2D 模型、动作和口型。窗口只读取随包资源，通过子进程管道与 DSH 交换全局任务状态、最近聊天的公开文本与动作。

顶部工具栏在鼠标移入时显示；关闭对话和设置后，鼠标移开便自动隐藏。工具运行进度不会锁住工具栏。使用 Tab 键操作时会保持控件可见，切换到其他窗口后恢复自动隐藏。

### 小肥鱼的待机场景

在桌宠的 **大小/动作 → 待机场景**，或 **设置 → 大肥鱼工作区 → 桌宠**，可以选「荡秋千」「吃白米饭」「躺床睡觉」。用「场景表情」给秋千和吃饭搭配开心、呆萌、满足、困倦或闭眼；聊天立姿时，同一个下拉框可试播「正面待机」「双眼闭合」「眼球移动与张嘴」「小幅转头」，每次播放一次，可以重复选择。当前场景不支持的选项显示为灰色，无法点击；回复或录音期间暂停手动试播。睡觉使用原画的卧姿闭眼。选「聊天立姿」可立即回到主模型。

选择「随机播放」后，每隔约 6–10 秒从当前场景支持的表情或动作中随机选一项，避免连续重复；立姿动作会播放完整，秋千和吃饭的动作速度不变。切换场景时自动更新候选范围，睡觉只有闭眼可用时保持闭眼。回复或录音时暂停随机播放，空闲后恢复；手动选择表情、动作或「场景默认」即可退出随机模式。随机播放不会重置待机场景的自动轮换计时。

在桌宠内修改自动轮换时间后，点击「保存轮换时间」「完成」、桌宠的关闭按钮，或工作区设置的「收回桌宠」，都会等待轮换时间保存成功。无效数值或保存失败时保留窗口和输入，显示错误；收回并重新打开、重新启动宿主后会读取已保存的时间。

吃白米饭使用坐姿双手吃饭立绘，7.2 秒一循环。角色坐在鲸鱼花纹大碗后，双手交替掌心朝下伸入饭堆，抓起后转腕送到嘴边，再闭嘴鼓腮。前面的米饭遮住伸进去的指尖，袖口始终连着手腕。大碗和双腿保持稳定，笑眼沿用原图，开心符号和咀嚼线随动作显隐。

「自动」从全局任务及当前聊天进入空闲开始计时。空闲 20 秒后开始荡秋千，再按停留时长轮换秋千和吃饭。默认秋千 84 秒、吃饭 36 秒，第一次秋千也使用同一时长。桌宠的 **大小/动作 → 自动轮换时间** 和 **设置 → 大肥鱼工作区 → 桌宠 → 自动轮换时间** 都可以分别设置 5–3600 秒的整数。桌宠中改完直接点「完成」，保存成功后关闭设置；数值无效或保存失败会展开提示并保留输入，修正后可重试。也可以点「保存轮换时间」保存并继续调整。两处设置同步生效并跨重启保留。修改时当前自动待机动作重新计时，动作本身的播放速度不变。

当地时间 22:00 至次日 06:00，连续空闲满两分钟后改为睡觉。输入、录音、新回复、工具活动和错误优先显示聊天模型。开启系统的减弱动态效果后，自动待机停在聊天立姿，手动选择场景显示固定姿态。

Agent 也可以为这一轮结束后的待机指定一个场景。例如 `fish_avatar_cue` 接受 `{"idleScene":"eat_rice","idleExpression":"content"}`。本轮回答和朗读结束后播放一轮，下次输入可以立即打断。

## 桌宠与聊天联动

桌宠常驻全局，聊天输入框里不再显示角色面板。打开或点选任意 DSH 会话后，桌宠的对话会自动使用这间最近打开的聊天，对话框中会显示发送去向。切换会话不会重建桌宠，也不会清空聊天草稿、轮换时间或场景选择。

所有会话的任务和工具状态都会汇总到桌宠；最近聊天的公开回复可驱动文字、表情和朗读。后台会话只贡献任务状态，不会把正文混入当前对话。重新打开历史会话只恢复进行中的活动，不朗读过去的回答。多任务同时进行时，一个任务结束不会让桌宠误回待机。

可以使用 DSH 原输入框的麦克风，也可以在桌宠里录音。麦克风依赖 DSH 的「语音输入」插件、已就绪的 SenseVoice 模型和麦克风权限。macOS 的「婷婷」在本机合成朗读，角色根据播放波形开合嘴巴；停止播报、关闭朗读、收回桌宠或自动切换聊天去向时，会取消当前音频。

最近聊天中的 Agent 可用 `fish_avatar_cue` 表达情绪、做一次动作或展示简短进度。例如 `{"emotion":"happy","action":"nod","progress":"检查完成"}`。当前聊天的定时任务回答也可以驱动桌宠的回复表情。

小肥鱼沿用原立绘的身体，五官按六张参考重绘。当前保留 10 段动作，已移除左右单眼闭合动作。65 个具名图层、17 个参数、6 个变形器和 7 个表情随插件提供。运行入口为 `lib/avatar/model/fish.model3.json`。程序使用 `lib/avatar/` 中已导出的资源；可编辑原画、模型工程和演示资料仅在本地保留，不随仓库或安装包发布。

## 使用

DSH 设置 → 大肥鱼工作区：

- **统一角色**：编辑角色名称、它的名字、对使用者的称呼和完整人设。可复制为新角色，删除未绑定角色。人设中可用 `{{selfName}}`、`{{ownerName}}`；旧手写正文原样保留。
- **与我私聊**：填写自己的个人情况、与鱼的关系和只用于本人私聊的相处规则，可另设私聊称呼，绑定 B站 UID、QQ号及专用会话。默认留空且停用，由使用者自己填写；不会把插件现有账号自动认作本人。
- **工作区绑定**：同一个角色可绑定多个工作区。工作区内的现有会话、新会话和子代理都按自身工作区选择角色，无需逐个勾选会话；工作区归属存在歧义时不推测角色。
- **覆盖检查**：分别展示常规会话、子代理、记忆/心情等内部调用的观测情况，以及 B站、QQ 保存的任务目标。可将目标所在工作区绑定到角色，不修改原插件的目标设置。
- **屏幕感知**：Mac 主显示器按需截图，开关和会话授权即时保存；本机预览、立即暂停，以及供支持图片的模型调用的 `screen_observe` 工具。

点击「保存控制台设置」后，后续请求使用新规则。多个设置页并发编辑时通过配置版本摘要校验，冲突会拒绝保存，避免覆盖别的页面。

## 屏幕感知（第一版）

仅支持 macOS 主显示器按需截图，不定时观察、不操作鼠标或键盘。设置默认关闭，位于「大肥鱼工作区 → 屏幕感知」。使用系统 `/usr/sbin/screencapture` 采集主显示器，大图通过系统 `sips` 缩放至最长边 1800px；临时目录和文件仅供当前用户访问，成功、失败、超时、取消后均清理。最近一次预览只保留在内存，暂停或重载后清空。

1. 更新后完整退出并重新打开 DeepSeek Harness，确保前端与后端一起载入新版；仅刷新设置页不保证后端更新。重启前先结束正在进行的任务。
2. 在屏幕感知页启用功能，勾选专用本机会话。每次勾选都即时保存，等待页面显示保存成功再返回聊天；上方的角色保存按钮仍只保存角色设置。保存失败时保留待重试设置，错误持续显示，页面的启用状态以服务端已保存值为准。
3. 点击「立即截图预览」检查采集效果；本次预览不调用模型、不写入 DSH 图片附件。首次使用可能需要在 macOS「系统设置 → 隐私与安全性 → 屏幕录制」授权 DeepSeek Harness 或实际启动它的程序，并按系统提示重启。
4. 回到授权会话，新发消息“请调用 screen_observe 看看我现在屏幕上的内容”。工具会检查该会话当前实际模型路由是否声明支持图片，再采集并返回 DSH 原生图片附件。只支持文字的模型在截图前被拒绝；第一版不额外配置视觉模型或转发到其他服务。
5. 「立即暂停」持久化关闭开关，中止在途采集并清空预览。重新启用或更改授权后，需要新一轮本机用户输入才能调用。

旧版只把勾选放入草稿，关闭设置页会丢失未保存修改；v0.5.2 改为即时保存。已保存的总开关不会因一轮对话结束、截图失败或插件重载自动关闭。当前轮次的调用证据到期只影响工具能否执行，不改总开关。保存失败时应先处理显示的原因，再重试；不要把草稿勾选当作已经启用。

已勾选会话但总开关关闭时，界面会明确提示；该会话后续的本机请求也会携带屏幕不可用原因，避免把暂停误报为插件未安装。DSH 使用 PTC 模式时，模型的直接工具清单只有 `run_code` 属正常现象，应在其程序中调用 `await tools.screen_observe({})`；工具执行端仍会核对屏幕授权。系统截图失败也可能由锁屏或显示源不可用引起，不能单凭报错就断定缺少屏幕录制权限。

屏幕授权不随角色或工作区继承。执行时必须是明确勾选的活跃独立会话、已领取本机 `source.kind=user` 的当前轮次；QQ、B站、后台输入混入时拒绝，内部工具图片上下文不算新用户来源。宿主缺少工具拦截、附件存储或模型能力接口时，AI 工具不可用，设置页会明确提示。`screen_observe` 由“屏幕感知”页的总开关和会话授权管理。

保存启用和工具截图前后会检查已知平台路由：拒绝已连接 QQ 或 B站任务的会话；B站生效配置无法读取时也拒绝。建议使用专用本机会话。AI 工具生成的截图会发送给该会话的模型服务，并按 DSH 附件机制留在会话历史；以后将此会话接到平台前，应先清理含截图的历史。屏幕模块不调用长期记忆写入接口，但其他插件是否从会话中提取内容由其自身设置决定。

打开屏幕页时，控制台会核对已勾选会话与 B站当前生效的目标。如果同一间会话两边都选了，页面和 B站下拉框旁会显示“从哪间改到哪间”。「带我设置 B站目标会话」会定位「刷B站 → 日常 → 自动刷在哪个会话」。只有「刷B站内容」属于独立的未勾选会话时才会推荐它。自己选好 B站目标，看到“自动刷会话：已保存”后点「返回屏幕感知」，再点「我已设置好，检查并继续启用」。控制台会按实际路由重新核验整份屏幕名单，保留原来的勾选。

「打开 Mac 屏幕录制设置」会直接打开系统设置的屏幕录制页面。仅跳转，不代替使用者授予权限；按系统提示允许 DeepSeek Harness 或实际启动它的程序，必要时重启后返回预览。跳转失败会显示手动打开路径。

v0.5.4 的屏幕接口会报告实际运行版本和权限引导能力；新版页面遇到旧后端时会停用尚未载入的跳转按钮，并明确提示完整重启。HTTP 空响应或非 JSON 响应会显示服务错误，不再把 JSON 解析异常误报成系统设置或屏幕录制权限失败。

屏幕设置独立存放在 `~/.dsh/fish-console/screen.json`（协议 v1），变更前备份在同目录 `backups/`；不迁移或改写角色配置。多页保存通过版本摘要防止相互覆盖，暂停会保留磁盘最新授权名单。临时文件清理不等于删除 DSH 已保存的会话附件。

## 本人私聊

统一角色保持鱼的共同性格和背景，私聊补充按当前角色单独保存，只在本轮确认属于本人私聊时追加。私聊称呼留空时沿用统一称呼；补充正文支持 `{{selfName}}` 和本轮的 `{{ownerName}}`。复制角色会复制相处规则的文字，但清空平台账号、会话选择并关闭启用开关。

1. 新建或选择一间专用会话，在「与我私聊」填写个人资料、相处规则和可选私聊称呼。
2. 需要本机 DSH 聊天也使用这层规则时，勾选对应会话。平台私信则填写数字 B站 UID 或 QQ号，并选择会话。先将会话所在工作区绑定到当前角色，再勾选专用私聊会话；这里的选择只授权专属私聊规则，不改变角色归属。
3. 保存控制台。只保存资料不会开启平台收发。
4. 点「连接并启用 B站私信」或「保存到 QQ 私聊绑定」。只写连接配置，不发送测试私信。QQ 未配置过时保存绑定但保持总开关关闭，需要去「通到QQ」完成连接服务设置；现有连接、群聊和其他私聊对象不搬移。

B站 0.8.7 和 0.8.8 共用一个互动入口。如果入口已有自动刷或公开互动，连接会报冲突，不停用原任务；额外私信名单中有其他账号时也不会覆盖。允许连接时会设置本人 UID、私信目标会话、只私信模式，并启用全天的本人私信接收，关闭该入口的公开 @ 轮询。已有自动公开动态的原目标会保留，不能选作专属私聊会话。

QQ 1.4.0 会把同一会话的回复转给其全部绑定，所以所选会话不能再连接群或其他私聊对象。个人关系正文始终留在控制台，不写入 QQ 或 B站的全局人设；专属称呼仅同步到可确认的对应记忆会话、QQ 私聊绑定，共用的心情份有称呼冲突时保留原值并提示。

运行时使用原生 `agent/inbox/claimed` 的当前轮输入证据：本机只认已勾选会话的 `source.kind=user`；QQ 结合锁定版本的原生私聊来源头和唯一账号绑定；B站结合锁定版本生成的纯私信包前缀、单一私信账号和专用路由。正文自称本人、昵称或粘贴账号不会成为身份凭据。混合公共输入、路由变化、未知版本或归属不明时不追加专属规则。重载后等待下一条新输入，不回放旧聊天来猜身份；子代理不继承这层补充。

B站 0.8.8 的宿主热配置可能与保存的配置文件不同。控制台在领取私聊输入、组装提示词及 B站私信回复前读取插件实际生效的本机配置；路由在本轮变化或接口不可用时不追加专属规则，也不会放行已经进入专属上下文后的 B站回复。只保留来源头和路由摘要，不保留私聊正文用于校验。

B站 0.8.8 的 volatile 配置兼容补丁位于 `patches/dsh-bili-subagent-0.8.8-volatile.patch`：先读取字段的实际值，避免错误使用默认值。补丁需单独应用；重新安装或更新 B站插件后应重新核对兼容性。控制台发现生效值与保存值冲突时会暂停相关写入。

已识别私聊的当轮不能调用 B站公开评论、动态或修改平台路由；B站私信回复只允许原绑定的本人 UID，工具的 `force` 参数也不能绕过这一项检查。关闭私聊身份只停用专属规则，不删除平台连接。

覆盖检查另显示「本人私聊规则：确认携带／未携带／来源不符」，修改资料后旧版本记录失效。入口记录只保存渠道与版本等元数据，不包含个人关系正文或完整账号。

## 名字和称呼联动

保存控制台时同步；新会话使用角色时补同步，后台每 30 秒核对重试。统一角色页提供「重新同步名字和称呼」和每个插件的独立结果，部分失败不会被显示为全部成功，也不影响控制台配置的保存。

- **记忆**：对应会话的 `selfNames`、`ownerNames` 跟随角色；所有绑定角色的对方称呼一致时同步全局 `userPronoun`。使用原生会话 ID，保留其他会话和所有非名称设置。该版本的 `/names` 接口会清洗历史记忆，因此这里只精准更新配置文件；插件每次使用时动态读取，无需修改历史正文。
- **心情**：通过原生设置接口更新已能明确归属的份，保留稳定 ID、已有绑定和心情记录。份内角色有冲突、混入未管理会话时不覆盖冲突项，不新增或拆分份。只有所有现有份均可归属、角色身份一致时同步全局默认名字和称呼；“TA 平时怎么叫你”是使用者叫它的昵称，单独保留。
- **B站**：通过原生设置接口更新全局 `ownerName`，同时核对宿主设置的保存结果。多个绑定角色的对方称呼不同则显示冲突；不覆盖任务提示正文、目标或收发开关。
- **QQ**：精准更新对应私聊绑定的称呼；群聊、其他对象、令牌和开关保留。未保存过 QQ 绑定时不创建配置，目标对象有歧义时不覆盖。

全局字段无法同时表示不同角色的值；遇到这种情况保留原值、显示部分同步或冲突，各工作区的角色绑定仍然有效。名称同步是配置证据，完整人设是否进入实际请求仍以覆盖检查为准。此功能不声称给所有内部专用模型调用注入完整性格或背景。

## 覆盖状态的含义

绑定、组装尝试和模型入口观测是三种不同证据：

1. **已绑定，等待请求**：配置决定这个会话使用哪个角色，尚无请求证据。
2. **已尝试注入**：经过 DSH 原生提示组装接口加入角色，尚未在模型入口确认。
3. **确认携带**：在 DSH `llm/stream` 入口确认有效系统输入包含当前版本的完整人设和统一身份。角色版本摘要会随名字、称呼或正文改变；改绑其他角色后，原来的成功请求也只作为历史记录，不会冒充当前覆盖证据。
4. **未携带／未绑定／归属不明**：分别代表有明确角色但缺少完整人设、没有配置角色、缺少可靠的会话归属。

模型入口观察只读：原请求（包括冻结对象）、流和插件内部 JSON 等专用提示保持原样，不重试或替换模型调用。到达入口不等于模型执行成功，也不保证模型一定遵循人设。没有经过 DSH 模型入口的外部请求无法观测；未出现的调用显示等待，不显示已覆盖。

显式 `sessionId` 优先用于归属；没有标识时仅使用仍然存活且可核对的 DSH 发起会话上下文。未知显式标识不使用另一个环境会话兜底；不按模型名、最近会话或聊天内容猜角色。普通请求使用 DSH 原生提示组装，DSH 的 complete 预设若移除了角色段，会在入口检查中显示未携带。

最近 200 条观测和组装尝试仅存在内存，重载后清空；只存时间、分类、已知会话 ID、角色和版本等元数据，不存聊天正文、请求提示词或凭证。覆盖检查页每 8 秒刷新，旧版本记录会标明。

## 兼容和扩展边界

- 工作区和会话名单来自 DSH `workspaceRegistry`、活跃 agents。未加载会话的头部由只读 `sessionQuery.listSessions()` 提供，标题由 `sessionProjectionCache.cachedSnapshot()` 提供；不自行解析私有日志或载入 Agent。没有这些可选接口时显示能力缺失，名称退回 ID。
- B站/QQ 的任务目标检查只读取已适配版本的保存配置，是路由提示而非任务已执行的证明。不支持的版本显示未适配，并跳过名称写入。
- 模型入口或工具 guard 缺失时显示对应能力不可用；不修改宿主文件、不替换 SDK、不对第三方插件做 monkey patch。
- 人设相关代码与插件任务检查分离：`roles.js` 管理结构和解析，`catalog.js` 处理宿主元数据，`policy.js` 组装角色与独立工具策略，`coverage.js` 只读观察，`integrations.js` 提供只读目标检查。`identity-targets.js` 计算全部角色的同步范围，`identity-adapters.js` 封装插件版本差异，`identity-sync.js` 串行核对重试；新增插件适配不改角色解析器。
- 私聊配置、路由识别、当前轮证据和连接写入分别位于 `private-profile.js`、`private-routing.js`、`private-runtime.js`、`private-connect.js`。平台差异集中在适配层，配置与原生来源证据都确认后才追加规则；不替换第三方消息处理器。
- 全局和会话工具由 DSH 与各插件提供，控制台默认接入全部可用工具。旧的工作区禁用列表会在升级时清理，提示词和执行端不再使用它。屏幕工具仍按屏幕授权决定是否进入清单或 SDK，并在执行前检查授权；私聊工具仍检查已识别的本人路由。后台定时任务和 QQ 收发等服务继续运行。

## 配置与迁移

控制台主配置位于 `~/.dsh/fish-console/config.json`（v7），修改前的原字节备份在 `backups/`。名称联动另会更新记忆、QQ 的名称配置，以及经原生接口更新心情、B站的名称配置。私信连接按钮经 B站设置接口更新自己的入口，或精准更新 QQ 的绑定配置。修改前的备份同样保存在控制台的 `backups/`，不写第三方源码或历史记忆正文。

旧 v1/v2/v3 配置迁移为一个稳定角色和一条工作区绑定，保留自称、称呼和完整人设；v4/v5 保留全部角色、工作区绑定和私聊资料，删除会话单独覆盖和父角色继承开关。旧版只有会话绑定的工作区需要在“工作区绑定”页重新选择角色；旧会话覆盖不再优先于工作区。v1–v6 的工作区工具禁用列表及旧工具开关一并移除。升级加载时先备份原文件，再写入 v7。v4 缺少的 `privateChat` 补为空白且停用。损坏或未来版本配置暂停角色应用和名称同步，不以默认配置覆盖原文件。v6 及更早的客户端不能向新接口保存，需刷新设置页后继续使用。

配置结构支持多个角色及其工作区绑定：

```json
{
  "version": 7,
  "roles": [{ "id": "role-default", "label": "角色", "selfName": "小肥鱼001", "ownerName": "老大", "persona": "...", "privateChat": { "enabled": false, "ownerName": "", "persona": "", "localSessions": [], "bili": { "uid": "", "sessionId": "" }, "qq": { "number": "", "sessionId": "" } } }],
  "bindings": { "workspaces": [{ "workspace": "/absolute/path", "roleId": "role-default" }] }
}
```

v0.3.1 起的联动使用当前 `lib/identity-*.js`，一次解析全部角色，避免多个角色分别同步时争抢全局字段。旧实现仅在本地归档，不参与运行、发布或测试。

## 验证

在 macOS 上运行 `FISH_CONSOLE_NATIVE_LAYOUT=1 node --test --test-concurrency=1 test/native-desktop-*.test.js` 会短暂打开测试桌宠，检查设置页远程控制、会话切换、轮换保存、控件间距、工具栏收起、右缘吸附和重启后的停靠位置。

`npm test` 运行角色迁移、工作区绑定、旧工具禁用列表清理、只读覆盖、并发保存、名称同步、私聊来源伪装、混合群聊、路由变化和历史正文不变等测试。设置 `FISH_CONSOLE_DSH_MODULES` 指向本机 DSH `node_modules` 时，增加真实 DSH 组装器、工具运行时、AgentLoop 输入领取与模型入口的隔离测试：不注册网络 provider，不调用外部模型，并验证 complete 预设缺失人设时不会显示已覆盖。`FISH_CONSOLE_PLUGIN_ROOT` 指向已安装插件目录时增加真实记忆和心情插件名称接口测试；`FISH_CONSOLE_BILI_ROOT` 指向 B站 0.8.8 源码时测试其实际设置接口，使用临时家目录和隔离账本。平台连接测试只提交配置，不调用发信、扫描或聊天端点。

现有本地链接安装可继续使用。宿主支持热重载时可以在插件页关闭再开启控制台；热替换不成功或运行中的后端缺少新能力时，需要完整退出并重开 DSH。设置页有协议版本与能力检查，旧客户端不能向新接口保存并覆盖绑定。

## 开发与更新 GitHub

本插件独立维护在 [zhuyu-zzyy/dsh-fish-console](https://github.com/zhuyu-zzyy/dsh-fish-console)，仓库根目录是包含本 README 和 `package.json` 的 `dsh-fish-console` 文件夹。上级工作区可以同时放其他项目，它们不属于本仓库。

本地链接安装直接使用这个目录中的源码，修改后无需复制到另一份项目。桌宠页面修改后收回并重新打开桌宠；宿主逻辑修改后重新加载插件或重启 DSH。推送到 GitHub 不会自动重启已运行的插件。

开始修改前，在仓库内用 `git pull --ff-only` 同步远端。修改完成后检查并提交：

```sh
npm test
git status
git diff
git add .
git diff --cached --name-only
git commit -m "说明本次修改"
git push origin main
```

仓库保留插件代码、测试、构建脚本和 `lib/avatar/` 中的运行资源。`artwork/` 全目录、`_archive/`、原画与模型工程、演示录音录像、设计文档、环境配置、凭据、聊天记录、截图、备份、依赖、缓存和打包产物由 `.gitignore` 排除，保留在本地。测试中的账号和凭据均为测试占位值；运行时个人设置保存在 `~/.dsh/fish-console/`。

安装包仅包含 `package.json` 的 `files` 清单，`lib/.npmignore` 进一步排除运行目录内误放的配置和数据。发布前用 `npm pack --dry-run` 检查实际文件列表，并核对暂存清单；不要使用 `git add -f` 强行添加已忽略文件。忽略规则不能移除已跟踪文件或改写历史，需要先对已跟踪的排除项执行 `git rm --cached`，本地原文件仍可保留。
